FIX 1 — R2R ROI formula missing landlord deposit from the denominator

File: artifacts/dealscore/src/lib/calculations.ts

Problem: calculateR2R's ROI and net yield both divide by inputs.setupCosts alone. Rent-to-Rent deals require a landlord deposit (refundable, typically 1-2 months' rent) as part of the cash invested to secure the arrangement — that deposit isn't tracked as an input at all, so it's silently missing from both the ROI calculation and the "cash invested" total shown in Show Workings. This currently overstates ROI significantly (audit found ~103% shown vs ~60% correct on a real deal).

Step 1 — Add the missing field to R2RInputs:

Find:

typescriptexport interface R2RInputs {
  monthlyRentPaid: number;
  rooms: number;
  rentPerRoom: number;
  occupancyRate: number;
  managementFeesPercent: number;
  monthlyRunningCosts: number;
  setupCosts: number;
}

Replace with:

typescriptexport interface R2RInputs {
  monthlyRentPaid: number;
  rooms: number;
  rentPerRoom: number;
  occupancyRate: number;
  managementFeesPercent: number;
  monthlyRunningCosts: number;
  setupCosts: number;
  landlordDeposit: number;

Step 2 — Fix the ROI and yield calculations to use total cash invested (setup costs + landlord deposit):

Find:

  const managementFees = grossMonthlyIncome * (inputs.managementFeesPercent / 100);
  const netMonthlyIncome = grossMonthlyIncome - managementFees;
  const monthlyProfit = netMonthlyIncome - inputs.monthlyRentPaid - inputs.monthlyRunningCosts;

  const netYield = inputs.setupCosts > 0 ? (annualProfit / inputs.setupCosts) * 100 : 0;

FIX 2 — PDF stress test uses interest-only formula regardless of mortgage type

File: artifacts/dealscore/src/components/DealScorePDF.tsx

Problem: The Stress Testing page's computeStScenario function always calculates the mortgage payment as a pure interest-only figure (stLoanAmount * rate / 100 / 12), even when the deal's mortgageType is 'REPAYMENT'. This produces the wrong stress-test numbers for any deal using a repayment mortgage — the payment shown will be too low, understating risk.

Find:

typescript  const computeStScenario = (offset: number) => {
    const rate = stBaseRate + offset;
    const mortgage = stLoanAmount * (rate / 100) / 12;
    const cf = stEffectiveRent - stTotalOpCosts - mortgage;
    const roi = stCashInvested > 0 ? (cf * 12 / stCashInvested) * 100 : 0;
    const payback = (stCashInvested > 0 && cf > 0) ? stCashInvested / (cf * 12) : Infinity;
    return { rate, mortgage, cf, roi, payback };
  };

Replace with:

typescript  const computeStScenario = (offset: number) => {
    const rate = stBaseRate + offset;
    let mortgage: number;
    if (props.mortgageType === 'REPAYMENT') {
      const monthlyRate = rate / 100 / 12;
      const n = props.mortgageTerm * 12;
      mortgage = (monthlyRate === 0 || n <= 0)
        ? (n > 0 ? stLoanAmount / n : 0)
        : (stLoanAmount * monthlyRate) / (1 - Math.pow(1 + monthlyRate, -n));
    } else {
      mortgage = stLoanAmount * (rate / 100) / 12;
    }
    const cf = stEffectiveRent - stTotalOpCosts - mortgage;
    const roi = stCashInvested > 0 ? (cf * 12 / stCashInvested) * 100 : 0;
    const payback = (stCashInvested > 0 && cf > 0) ? stCashInvested / (cf * 12) : Infinity;
    return { rate, mortgage, cf, roi, payback };
  };

Before making this change, check one thing: for dealType === 'BRRR', confirm whether props.mortgageType/props.mortgageTerm are the correct fields to use for the refinance mortgage, or whether BRRR tracks its own separate mortgage-type field (since stBaseRate for BRRR already pulls from props.brrrInputs.newMortgageRate rather than the shared props.mortgageRate). If BRRR has its own type/term fields, use those conditionally instead. Read the BRRRInputs interface and how props.brrrInputs is used elsewhere in this file to confirm before finalizing this edit.
