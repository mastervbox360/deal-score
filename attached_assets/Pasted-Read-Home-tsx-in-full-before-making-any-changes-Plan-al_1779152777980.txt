FIX 1 — iOS dropdown fix
Find the address suggestions dropdown. Each suggestion item is currently a <div> with onMouseDown. The iOS bug is:

User taps a suggestion
touchstart fires on the suggestion
blur fires on the input → setTimeout(() => setShowSuggestions(false), 150) starts
click fires on the suggestion — but 150ms is not enough time on iOS; the dropdown is already gone

Replace the existing onBlur on the Input with a version that checks if the related target is inside the suggestions dropdown:
Find:
tsxonBlur={() => setTimeout(() => setShowSuggestions(false), 150)}
Replace with:
tsxonBlur={(e) => {
  const related = e.relatedTarget as HTMLElement | null;
  if (related && related.closest('[data-suggestions]')) return;
  setTimeout(() => setShowSuggestions(false), 200);
}}
Then find the suggestions container <div> (the one with position: 'absolute', zIndex: 1000) and add data-suggestions="" and tabIndex={-1} to it:
Find:
tsx<div style={{
  position: 'absolute',
  zIndex: 1000,
  background: '#fff',
Replace with:
tsx<div
  data-suggestions=""
  tabIndex={-1}
  style={{
    position: 'absolute',
    zIndex: 1000,
    background: '#fff',
Then for each suggestion item <div>, replace onMouseDown with onPointerDown and add a onTouchStart handler that prevents the default blur:
Find:
tsxonMouseDown={() => selectSuggestion(suggestion)}
Replace with:
tsxonPointerDown={(e) => { e.preventDefault(); selectSuggestion(suggestion); }}
The e.preventDefault() on pointerdown stops the input from losing focus before the selection fires, which fixes the iOS tap-to-select behaviour.
